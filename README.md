# MrCHAO — смены и финансы

Веб-приложение для графика смен и финансового учёта сети **MrCHAO**. Работает на компьютере, iPhone и Android, устанавливается как обычное приложение (PWA). Бесплатно: хостинг — GitHub Pages / Netlify / Cloudflare Pages, синхронизация — бесплатный тариф Firebase.

> **Сайт команды:** <https://art02041670rus-dev.github.io/Smena/> — уже опубликован на GitHub Pages. Код команды и Firebase прописаны в `config.js`, поэтому сотрудникам достаточно открыть ссылку, зарегистрироваться по email и выбрать своё имя в команде.

**Что уже умеет**

- календарь на месяц и список смен;
- стандартная смена **10:00–21:00** в один клик;
- **разделённые смены**: например, Анна 10:00–15:00 и Пётр 15:00–21:00;
- несколько смен в один день, у каждого сотрудника свой цвет;
- проверка, что день полностью покрыт с 10:00 до 21:00 (и предупреждение о «дырках»);
- запрет пересекающихся смен у одного сотрудника;
- часы и количество смен по каждому сотруднику за месяц;
- история изменений: кто и когда добавил или изменил смену;
- синхронизация между устройствами в реальном времени (Firebase Realtime Database);
- **финансовый учёт по сменам**: таблица «Точка / ФИО / Дата» + выручка, нал, безнал, инкассация, обед, размен, остаток; итоги за месяц и настраиваемые колонки;
- офлайн-режим и установка на домашний экран;
- экспорт в CSV для Excel и резервная копия в JSON;
- тёмная и светлая тема.

## 1. Быстрый старт

Скачайте папку и откройте `index.html` в браузере на компьютере — приложение сразу работает в локальном режиме (данные хранятся в браузере этого устройства).

Чтобы пользоваться с телефона и синхронизировать график с коллегами, нужно:

1. включить синхронизацию (раздел 2);
2. выложить папку на бесплатный хостинг (раздел 3);
3. установить приложение на телефоны (раздел 4).

---

## 2. Синхронизация через Firebase (бесплатно, ~10 минут)

Firebase — облачная база данных Google. Бесплатного тарифа **Spark** с запасом хватает небольшой команде (1 ГБ хранилища, 10 ГБ трафика в месяц, 100 одновременных подключений).

### 2.1. Создайте проект

1. Откройте <https://console.firebase.google.com> и войдите в Google-аккаунт.
2. **Add project / Создать проект** → любое название (например, `smena`) → продолжить.
3. Google Analytics можно отключить → **Create project**.

### 2.2. Создайте Realtime Database

1. В левом меню: **Build → Realtime Database**.
2. **Create Database**.
3. Регион — любой ближайший (например, `europe-west1`).
4. Режим — **Start in test mode** → **Enable**.

### 2.3. Опубликуйте правила доступа

1. На странице Realtime Database откройте вкладку **Rules**.
2. Скопируйте туда **всё содержимое файла `database.rules.json`** из папки проекта.
3. Нажмите **Publish**.

> ⚠️ Без этих правил приложение покажет «Нет доступа к профилю» и не пустит дальше. Правила задают роли и защищают финансы: сотрудник видит только свою команду и может менять финансы только текущей смены; менеджер — за любой день своих команд; администратор — всё.

> В правилах уже прописан email администратора `artem_rusan@mail.ru`. Если он изменится, замените его в `database.rules.json` (в тексте правил он встречается несколько раз) и опубликуйте заново.

### 2.4. Скопируйте конфигурацию

1. Нажмите шестерёнку рядом с **Project Overview** → **Project settings**.
2. Вкладка **General** → блок **Your apps** → значок **Web `</>`**.
3. Введите любое имя приложения → **Register app**.
4. Скопируйте объект `firebaseConfig` — он выглядит так:

```js
const firebaseConfig = {
  apiKey: "AIzaSy...",
  authDomain: "smena-12345.firebaseapp.com",
  databaseURL: "https://smena-12345-default-rtdb.europe-west1.firebasedatabase.app",
  projectId: "smena-12345",
  storageBucket: "smena-12345.appspot.com",
  messagingSenderId: "1234567890",
  appId: "1:1234567890:web:abcdef"
};
```

Важно, чтобы в конфигурации был `databaseURL` (адрес базы). Если его нет — откройте Realtime Database и скопируйте адрес из шапки страницы, затем добавьте строкой `databaseURL: "..."` в конфигурацию.

### 2.5. Включите вход по email и создайте аккаунты

1. В Firebase откройте **Authentication → Sign-in method** и включите **Email/Password**.
2. Откройте сайт. Появится экран **«Вход»**.
3. **Администратор** (`artem_rusan@mail.ru`): вкладка **«Регистрация»** → имя, email, пароль (не короче 6 символов). Роль администратора присваивается автоматически по email.
4. **Сотрудники**: **«Регистрация»** → имя, email, пароль → ввести код команды → выбрать своё имя в списке сотрудников.
5. **Менеджеры**: администратор открывает **Настройки → Участники и роли**, выбирает роль **«Менеджер»** и при необходимости привязывает сотрудника.
6. Если у менеджера несколько команд, он переключается между ними кнопкой с квадратами в шапке или в настройках.

Конфигурация Firebase и код команды уже прописаны в `config.js` — на устройствах сотрудников ничего вводить не нужно, кроме кода команды при первом входе.

**Проверка:** в правом верхнем углу должен появиться зелёный индикатор **«Онлайн»**. Добавьте смену на одном устройстве — она появится на другом в течение секунды.

## 3. Бесплатная публикация сайта

Приложению нужен адрес в интернете (HTTPS), чтобы работали установка на телефон и офлайн-режим.

### GitHub Pages (бесплатно навсегда)

1. Зарегистрируйтесь на <https://github.com>.
2. Создайте новый репозиторий, например `smena` (можно Public).
3. Загрузите все файлы проекта в корень репозитория (`index.html`, `app.js`, `styles.css`, `config.js`, `database.rules.json`, `manifest.webmanifest`, `sw.js`, папку `icons`).
4. **Settings → Pages** → Source: **Deploy from a branch** → Branch: `main`, папка `/ (root)` → **Save**.
5. Через минуту сайт будет доступен по адресу `https://ВАШ-ЛОГИН.github.io/smena/`.

### Netlify Drop (без командной строки)

1. Откройте <https://app.netlify.com/drop>.
2. Перетащите папку с проектом в окно браузера.
3. Получите ссылку вида `https://random-name.netlify.app`. Бесплатный тариф подходит.

### Cloudflare Pages

Аналогично: создайте проект, загрузите папку, получите адрес `*.pages.dev`.

> После обновления файлов просто загрузите новую версию — service worker сам подтянет изменения (стратегия «сначала сеть, потом кэш»).

## 4. Установка на телефон и компьютер

- **iPhone / iPad (Safari):** откройте ссылку → кнопка «Поделиться» (квадрат со стрелкой) → **«На экран "Домой"»** → «Добавить».
- **Android (Chrome):** откройте ссылку → меню ⋮ → **«Установить приложение»** (или «Добавить на главный экран»).
- **Windows / macOS (Chrome, Edge):** значок установки в адресной строке → «Установить».

После установки приложение открывается в отдельном окне, без адресной строки, и работает офлайн. Данные, введённые без интернета, сохранятся и отправятся в облако при появлении связи.

## 5. Как пользоваться

**Роли и доступ.**

- **Сотрудник** — видит график своей команды, может добавлять и менять смены. Финансы может заполнять **за 15 минут до начала смены и в течение суток после её окончания** (на случай ошибок и задержки). В остальные дни поля заблокированы.
- **Менеджер** — видит и ведёт график подключённых команд, может менять финансы за **любой день**. Его правки помечаются значком **M**; при наведении видно имя и время.
- **Администратор** — полный доступ ко всем командам, без пометок. Назначает менеджеров в **Настройки → Участники и роли**.

**Сотрудники.** Вкладка «Команда» → «Добавить» (доступно менеджеру и администратору). У каждого свой цвет — по нему смены видны в календаре. Новый сотрудник при первом входе выбирает своё имя в списке команды.

**Обычная смена.** Нажмите на день → «Добавить смену» → выберите сотрудника → нажмите «Полная 10:00–21:00» → «Добавить смену».

**Разделённая смена.** В тот же день добавьте две записи:

- Анна: 10:00–15:00;
- Пётр: 15:00–21:00.

Приложение проверит, что день покрыт с 10:00 до 21:00, и покажет зелёную плашку. Если есть разрыв — предупредит, например «Не покрыто: 15:00–21:00».

**Изменение и удаление.** Нажмите на смену в списке или на карандаш в дне. Удаление — корзина (с подтверждением).

**Итого.** Вкладка «Итого»: часы и количество смен по сотрудникам, дни с разрывами покрытия, история изменений. Оттуда же можно выгрузить CSV для Excel, сделать резервную копию и распечатать месяц.

**Кто менял график.** Каждое действие пишется в историю с именем сотрудника (имя задаётся в настройках). Так видно, кто поставил или убрал смену.

**Финансовый учёт.** Вкладка **«Учёт»**. Строки — это смены месяца. Сверху идут «Точка», «ФИО сотрудника» и «Дата», ниже через «пропуск» — начало смены, обед, выручка, наличные, безнал, инкассация, остаток в кассе и размен.

- **Безнал** считается как `Выручка − Наличные` (наличные вводит касса).
- **Остаток в кассе** — `Наличные − Инкассация`; размен в остатке не учитывается и вводится отдельной колонкой.
- Любое рассчитанное число можно переписать вручную — просто введите своё значение в поле. Очистите поле, чтобы вернуть авторасчёт.
- Внизу таблицы — итоги по всем суммам за месяц.
- Кнопка **«Настроить колонки»** позволяет переименовать и скрыть базовые колонки, добавить свои (текст, сумма, время) и изменить порядок.
- Те же поля доступны в форме смены: откройте день → смену → «Финансовый учёт».
- Данные синхронизируются вместе со сменой и попадают в CSV и резервную копию.

## 6. Данные и резервные копии

- В локальном режиме данные лежат в `localStorage` браузера.
- В режиме синхронизации — в Firebase, плюс копия на каждом устройстве (для офлайна).
- **Резервная копия:** «Итого» → «Резервная копия» (JSON). Восстановление — «Восстановить»: файл заменит текущий график.
- Если очистить данные браузера, локальная копия исчезнет, но облачная останется — просто откройте сайт снова.
- Чтобы полностью удалить команду, удалите её данные в консоли Firebase (Realtime Database).

## 7. Структура проекта

```
index.html            — каркас приложения
styles.css            — оформление (тёмная/светлая тема, мобильная вёрстка)
app.js                — вся логика: вход, роли, календарь, смены, финансы, синхронизация
config.js             — общие настройки команды (код + Firebase), заполняется один раз
database.rules.json   — правила доступа Firebase (скопировать в Rules → Publish)
manifest.webmanifest  — параметры установки как приложения
sw.js                 — service worker (офлайн-режим)
icons/                — иконки приложения
tools/make-icons.ps1  — скрипт генерации PNG-иконок (нужен только для замены иконок)
```

Сборка не нужна, зависимостей нет. Это обычные HTML/CSS/JS.

**Модель данных в Firebase:**

```
users/<uid>/            { name, email, role: employee|manager|admin,
                          memberships/<код команды> { empId, role } }
teams/<код команды>/
  name
  employees/<id>        { name, color }
  members/<uid>         { name, role, empId, at }
  shifts/<id>           { date, empId, start, end, note, by, at, tsStart, tsEnd }
  fin/<id смены>        { values: { колонка: значение }, meta: { колонка: { by, at, role } } }
  finance               { title, columns: [...] }
  log/<id>              { at, by, action, details }
```

График и финансы лежат в разных ветках: так правила Firebase могут разрешить сотруднику менять расписание, но запретить правку финансов за прошлые дни. Каждая смена — отдельная запись, поэтому одновременные правки разных людей не затирают друг друга.

## 8. Ограничения и что можно улучшить

- Часовой пояс не учитывается — даты и время вводятся вручную, как в бумажном графике.
- Нет push-уведомлений и заявок на отпуск.
- Нет интеграции с Google Calendar.
- Восстановление пароля — через письмо Firebase; если письмо не приходит, проверьте папку «Спам».

## 9. Частые проблемы

**«Нет доступа к профилю» / «Нет доступа».**
Опубликуйте правила: Firebase → Realtime Database → **Rules** → вставьте `database.rules.json` → **Publish**. После этого нажмите «Повторить» или войдите заново. Проверьте, что в Firebase включён вход **Email/Password**.

**«Не удалось загрузить график» / «Ошибка» в правом верхнем углу.**
Проверьте: правильный `databaseURL` в `config.js`, правила доступа опубликованы, интернет есть. Нажмите «Повторить» или откройте настройки.

**Изменения не появляются у коллег.**
У всех должен быть одинаковый **код команды** и одинаковая **конфигурация Firebase**.

**Не устанавливается на iPhone.**
Установка работает только в Safari и только по HTTPS-адресу (не по `file://`).

**Пропали данные на телефоне.**
Скорее всего, очищены данные браузера. Облачная копия осталась — откройте сайт заново. Резервные копии лучше делать периодически.

**Смена «не покрыта», хотя люди есть.**
Проверьте время: покрытие считается строго для интервала 10:00–21:00. Например, 10:00–15:00 и 15:00–21:00 покрывают полностью, а 10:00–14:00 и 15:00–21:00 — нет (дырка 14:00–15:00).
